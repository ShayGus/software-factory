# Vision

Software Factory exists to make what one person asks for become what gets built.
A technically clean implementation is insufficient when the request was misunderstood, a requirement disappeared from the plan, or worker instructions narrowed the intended outcome.
The system preserves product meaning from the original words to the delivered behavior.

## A continuous path from intent to evidence

FirstMate remains the conversational participant and execution supervisor.
The factory adds explicit understanding, design, an ordered dependency-aware plan, detailed implementation tasks, checked worker instructions and product review against the original request.
Shared records make the reasoning and evidence inspectable across sessions and workers.
The operator should be able to identify missing behavior and trace every brief to its plan without reconstructing chat history.

## One person, one complete system

A fresh clone and one setup command should produce a working FirstMate folder.
Opening Claude there should expose the factory, backlog and management screens without another agent session assembling the pieces.
The installation can reproduce itself from public sources, update from chat and develop its own code through the same supervised workflow.
Private projects, decisions, settings and data belong to that installation and never travel with a source clone.

## Honest progress and proportionate control

Execution-task state and product completeness remain separate.
Passing technical checks does not prove the requested product exists; missing, stale, blocked and untested evidence stays visible.
Independent work can proceed while genuine product questions remain explicit decisions.
Existing FirstMate lifecycle, worktree isolation, delivery modes and approval boundaries remain authoritative.
The system adds no competing scheduler or permanent hierarchy of managers.

## Focus

Serve one operator and their projects with open-source components and understandable ownership boundaries.
Reuse existing code and settled decisions before rebuilding them.
The factory screens perform canonical product edits; tasks-axi and Scotty edit execution tickets in one Beads database.
The [product design](factory/Software_Factory_Design.md#1-decision-and-scope) and [product purpose](factory/PRODUCT.md) supply the detailed methodology and scope.
The [FirstMate vision](docs/firstmate-vision.md) remains the execution layer's guiding contract.
